# Runtime dependencies.
#
# fast-flights pulls selectolax, primp and typing_extensions in as its own
# dependencies, but two of those are now imported *directly* by this project
# and so belong here in their own right: browser.py parses the rendered DOM
# with selectolax, and search.py drives primp to force hl/curr on the text
# query. Relying on a transitive dependency for something you import
# yourself is how a working checkout and a broken CI run end up disagreeing.
fast-flights>=2.2
PyYAML>=6.0
selectolax>=0.3
primp>=0.6

# Not imported here at all. fast-flights needs it and does not always get it
# installed - CI failed with "No module named 'typing_extensions'" on a
# clean runner while every local checkout was fine, because locally it had
# arrived as somebody else's transitive dependency.
typing_extensions>=4.0

# The IANA timezone database. `alerts.py` and `cli.py` both do
# ZoneInfo("America/Costa_Rica"), and the whole two-emails-a-day budget is
# keyed on Costa Rican local time.
#
# Linux ships a system tzdb, so CI has never needed this and never will -
# which is exactly why it went unnoticed. Windows ships none, and `zoneinfo`
# falls back to this package. Rebuilding the venv on 2026-08-23 turned every
# timezone-aware test into a collection error:
#
#     ZoneInfoNotFoundError: 'No time zone found with key America/Costa_Rica'
#
# It had been arriving as somebody else's transitive dependency, the same
# way typing_extensions did above. This is the mirror image of that bug:
# there it was green locally and red in CI, here it is green in CI and red
# on the only machine that actually runs the tracker.
tzdata>=2024.1
